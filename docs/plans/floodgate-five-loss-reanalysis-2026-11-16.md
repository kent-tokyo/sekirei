# Floodgate 5敗局の再分析計画（2026-11-16）

状態: **P0〜P4の有界診断を完了**。結果は[再分析記録](../experiments/floodgate_v054_r6_rescue_2026-11-16/REANALYSIS.md)。第9局103手目に損失縮小候補が残ったが、勝敗の救済、当時の原因、棋力向上は未証明。担当は主担当、独立担当は方法と結果の反証を受け持つ。エンジン計算は逐次実施した。

目的は、保存済み5敗局から「実戦手より良い合法な分岐」と、Sekireiがその手を選べなかった原因を見つけること。通常局面の完全な非敗証明を開発の前提にはしない。改善案の採用資格は別対局で確認する。

## 前回から変える判断

1. **材料評価をr6の審判にしない。** 第10局144手目の代替`4d4e`は初回のr6・共通深さ13・14で実戦手より353・455cp高かったが、今回の400万節点比較では優位が消えた。既知の浅い差を採用根拠にせず、順位変動の対照例とする。
2. **5局の全自分手番を対象にする。** 合法再生JSONで44＋69＋57＋72＋96＝338手番を確認した。初回20探索のプロセス時間合計は1.723秒。厳密な速度測定ではないが、全手番の粗い走査を小さな上限で試す費用根拠になる。大駒取り・王手・4手番おきだけでは敗着の前後を飛ばす。
3. **浅い探索と実戦手の一致も調べる。** 同じ探索が同じ弱点を再現し得るため、一致を除外理由にしない。評価の持続的な悪化や深さでの順位変動も候補にする。
4. **得点を、その得点を出した手と結び付ける。** 打切り中の返却`bestmove`と最後の完了反復のPVは異なる場合がある。既存の走査91行には3件（第10局112・120手目、第4局70手目）の不一致がある。その得点を返却手の値として扱わない。前回の完了した固定root比較はこの問題とは別。
5. **`exact`と同値反復を過大評価しない。** `completed_bound`は完了反復の探索境界で、選択的探索による値。理論的な勝敗の証明ではない。同条件2回の同値は再現性の確認であり、独立した棋力証拠ではない。追加計算は同じ探索の反復より、深さ・節点量・相手の応手による反証へ使う。
6. **参照エンジンの技術確認を全分析の待ち条件にしない。** 固定YaneuraOuソースの[`eval`](https://github.com/yaneurao/YaneuraOu/blob/c1b80eaa09fe13d5f12b1599d1ae4d53c224de30/source/usi.cpp#L323)は`trace_eval()`、整数評価の出力は[`e`](https://github.com/yaneurao/YaneuraOu/blob/c1b80eaa09fe13d5f12b1599d1ae4d53c224de30/source/usi.cpp#L367)。`e`は実機で応答し、事前固定12局面の静的整数評価がSekireiのr6と12/12一致した。次は探索差と相手の反撃を確認する。

前回の各測定値と試行上限は[監査記録](../experiments/floodgate_v054_r6_rescue_2026-11-16/RESULTS.md)に保持する。`NO_ROBUST_RESCUE_CONFIRMED_EVALUATOR_DISAGREEMENT`を今後の一律停止条件にはしない。本計画は新しい探索的な診断であり、過去の統計試行・D7の学習pilot・採用条件を延長または再解釈しない。

### P0: 既存記録の使い方

- 基準はv0.5.4 commit `1ce96c5a9c87b1ffcb68d86cb74ec3cb27eb474b`、r6 SHA-256 `634bdf527e7306045c8278df1d5311777561dfb09c1ebe6829ff3f4d883cc469`、HalfKP absolute、FV_SCALE=24。診断の64MiB TT・1Tと、実戦の256MiB・4Tを明記する。
- 全履歴から局面を復元し、期待SFEN・手番・hash・合法性を照合。得点はSekirei側の符号へ揃える。打切り時は完了反復の手・得点・PVを一組として扱い、未完了の返却手へ得点を流用しない。
- 完全に同じ入力・設定の既存結果は再利用する。欠けたiteration traceだけのために再実行しない。不一致行は完了PVで対応を復元できた場合だけ使い、できなければ未実施として埋める。
- YaneuraOuの`e`応答が得られたら、5局から手番・駒打ち・成駒・捕獲を含む12局面を先に固定し、`halfkp_oracle`と静的整数評価を照合する。符号・尺度・評価補正の差はソース上の意味を確認し、結果を見て許容差を調整しない。生NNUE出力が一致しない場合は「同一評価器の別探索」と呼ばない。
- `EvalDir/nn.bin`のhash、FV_SCALE、Threads、Hash、定跡offを固定。水匠の重み・評価値は用いない。YaneuraOu＋r6は探索経路の照合であり、評価器として独立ではない。`e`が使えない場合も、全338手番の分析は継続する。

### P1: 候補を選ぶ規則

各手番で完了反復の手、得点、深さ、節点、PV、停止理由を保存する。前後局面の得点差は候補抽出にだけ使い、実戦手の損失量とは呼ばない。

各局から最大4局面を選ぶ。優先順は、(a)次の2自分手番でも低い得点が続く悪化区間の直前を悪化幅順に2件、(b)完了反復で候補手が変わった局面を1件、(c)実戦手と解析手の不一致を1件。(a)は同じ符号へ揃えたcpで「現在得点−max(次の自分手番の得点、その次の得点)」を使う。mate表示や必要な完了得点がない場合は通常cpの順位へ混ぜず別記する。trace欠落の(b)は不明とする。同点は手数順、重複や不足は(a)の次順位で補う。実戦手と浅い第一候補が同じ局面も(a)(b)で残す。第10局144手目は同局4枠の1つを予約して既知の未解決例として含め、21局面目や独立例に数えない。

この最大20局面だけ、同じ親局面・同じ評価器から実戦手と代替手を強制rootで比較する。候補の得点を実戦手後の得点の符号反転だけで代用しない。順位は粗い手掛かりであり、深さが異なる得点差を確定値として並べない。

### P2: 深い比較と判定

実施時には第10局144手目＋他対局の3局面を選んだ。固定した4局面は第2局26手目、第3局54手目、第9局103手目、第10局144手目。以下は当時固定した選択・比較規則として保持する。

4局面を決めた後、各局面で100万節点の自由探索を1回行う。浅い第一候補と実戦手が同じ例でも、ここで別手が現れるかを調べられる。その後、実戦手と、P1/P2自由探索の完了反復で得た異なる代替手を深い反復から最大2つ、計3手までに固定して強制root比較へ進む。同じ手は重複させない。代替手が得られない局面は候補不足として残し、合法手列の先頭から適当に補わない。`--root-candidates N`は合法手生成順の先頭N件を調べる機能で、上位N手のMultiPVではないため、その用途では使わない。

各手を冷起動・同じ親履歴から100万節点と400万節点で比較する。さらに400万節点側で各手が完了した深さの最小値を共通深さとし、一度ずつ比較して深さ差による見かけの優位を確認する。この追加対照にも400万節点の上限を付け、到達できなければ未解決とする。前回の100万節点到達を理由に候補を否定せず、今回は最初から二段階を固定する。400万節点でも不足なら未解決として終了する。

進める目安は、両方の節点段階で同じ代替手が実戦手より150cp以上高く、共通深さでも順位が同じで、返却手/PV/履歴が整合すること。この150cpは分析の優先順位であり、勝率や非敗の境界ではない。−171cpという値だけを理由に「救えない」と判定しない。単独の大きな値だけで候補を採らず、逆転や上限打切りも一緒に保存する。今回この優先条件を満たしたのは第9局103手目の`4e4d`のみ。実戦`4g4h`に対して100万節点で+410cp、400万節点で+397cp、共通深さ15で+459cpだった。ただし候補の評価はなお負で、勝敗を救えることは示していない。第2局26手目、第3局54手目は150cp未満、第10局144手目は400万節点で優位が反転した。

### P3: 第9局103手目の分岐を反証する（完了）

P3aは事前固定済みの`p3a-contract.json`に従い、第9局103手目を第一対象、第10局144手目を順位変動の対照とした。固定YaneuraOu＋同じr6の1T・64MiB・定跡offで、各局面の自由探索1回と固定2手、合計6呼出し、各100万節点を完了。契約とr6・実行ファイル・P0/P2入力のhashを確認した。`searchmoves`指定時は返却手が指定手と一致し、最終PV初手も一致した。第9局は代替`4e4d`が自由探索で選ばれ、実戦`4g4h`の−866cp upperboundに対して−407cp exact。第10局の両固定手はupperboundで順位を確定できない。別探索器間の深さや節点の数値を同等と見なさない。

P3bはP3a後に第9局103手目の実戦`4g4h`と代替`4e4d`を固定。双方の相手手番をSekireiとYaneuraOuで探索し、異なる観測応手をその後2ply追跡した。計10呼出し、最大4ply、全結果完了。実戦後は両探索器が`2i3h+`を選び、代替後はSekireiが`2i3h+`、YaneuraOuが`2i3h`を選んだ。両方を合法再生し、履歴hashとSFENを保存した。第10局はP2の不通過を上書きする新情報がなく、P3bの対象に追加しなかった。短いPVの終端評価だけで勝敗を決めず、詰みの証明探索も追加しない。

報告は「計算量を増やしても損失縮小が残る」「実戦で粘れる可能性のある分岐」「詰み等の終局を証明できた」を区別する。候補なしと未解決も局面別に明記する。

### P4: 強化へつなぐ条件

今回の結論は[再分析記録のP4](../experiments/floodgate_v054_r6_rescue_2026-11-16/REANALYSIS.md#p4-5敗ごとの到達点と次の仮説)に5敗別で記載。第9局103手目の実戦4T・時間制限・探索状態が冷起動1Tと異なるroot選択を生んだ可能性は残る。後続のコード監査で、実戦CSAはUSIのLazy SMPではなく履歴付き`Searcher`とRayon YBWを使うこと、探索割当は`T11`そのものではなく11,733msであることを確認した。既存のUSI/Hash64/11秒の12呼出しはCSAの原因判定に使わず、[CSA経路に合わせた次の計画](floodgate-game9-ply103-csa-choice-2026-11-16.md)で再現と状態差を調べる。

分岐が見つかったら、探索量不足、手の順序/枝刈り、評価の弱点、時間配分、序盤選択のどれを次に調べると最も情報が得られるかを順位付けする。1T冷起動だけでは当時の4Tの失着原因を断定しない。実戦ログの時間情報は使うが、保存されていないTT・履歴表・thread状態を再現したとは言わない。

再現する合法代替が1件あれば、局所的な原因診断や正しさの修正に進める。NNUEの順位学習候補を作るには、既存D7計画どおり元対局をまたぐ2件以上の同種問題と、独立した訓練/開発/確認入力を要する。今回の5局はすべて開発用で、新しいhold-outにはしない。既知局面の改善率を棋力向上とせず、採用には既存の独立H1等の条件を適用する。

今後のFloodgateは通常の外部棋力確認として使う。次に対局する際は既存の`--analysis-dir`を有効にし、重み、得点/PV、深さ、節点、使用時間、割当時間を保存する。今回の分析を始めるために追加対局は不要。
