## 初回は40局面、計算8分以内で違いを見つける

5敗局の合法再生済み自分手番から、各局8局面を手数順に等間隔で選ぶ。件数Nに対し0始まりの `floor(k*(N-1)/7), k=0..7` を使う。第10局144手目が含まれない場合は、その局の最後の選択枠と入れ替える。この例は既知の未解決例として明示する。実行前に局面リスト・履歴・入力hashを保存し、結果を見て局面を足さない。

| 段階 | 作業 | 初回の上限・成果物 |
| --- | --- | --- |
| 1. 読取りを合わせる | 40局面の静的整数評価を照合する。うち12局面で先後・捕獲・成駒・持駒・玉移動を確認し、増分評価と作り直した評価も照合 | 起動を含め60秒。数値一致、説明できる変換差、未解決の不一致を記録 |
| 2. 両エンジンで走査する | 各局面を10万節点で探索し、推奨手・完了反復の評価値・深さ・節点・PVを保存 | 40局面×2エンジン。1呼出し2秒、段階合計160秒まで |
| 3. 最大6局面を掘る | 不一致の最大4局面と、一致する対照2局面について、同じ親局面から候補2手を両エンジンで強制して比べる | 1手10万→100万節点の二段階。最大48呼出し、各5秒、段階合計240秒まで |
| 4. 改善仮説を選ぶ | 残った差を手順とコードに結び付け、次に変更する箇所と最小検査を一つ決める | 局面別の原因候補、根拠、反例、未解決点を報告。追加探索なし |

起動・停止確認を含め初回の全体上限は480秒。1T、同時エンジン1個、Hash 64MiB、定跡・ponder・投機探索off、RSS合計1.5GiB以内、出力128MiB以内とする。各呼出しではTTと探索履歴表を初期化し、局面までの着手履歴は保持する。既存binaryを優先する。ビルドが必要なら別枠1job・5分・追加出力1GiBまでとし、当初の範囲を超えれば未実施部分を記録する。

開始時に競合する計算job、メモリ圧迫、保存先の空きを確認する。通常のブラウザやWindowServerのCPU使用率だけを理由に待機しない。固定節点数の診断として進め、時間上限に達した局面は未完了にする。メモリ圧迫、空き容量不足、二重起動、停止不能があれば止める。ここでの経過時間から速度差を主張しない。

## 差の大きさだけで候補を決めない

段階3の不一致枠は、比較可能な完了反復がある局面のうち、(a)推奨手が違い、揃えた評価符号も逆のもの、(b)その他の推奨手不一致、の順に選ぶ。同順位は対局ID・手数順、1局から最大2局面。初回から数値差の閾値に頼らず、優先順位だけで調べられるようにする。推奨手一致枠は手数帯が近い別局面を対局ID・手数順で選ぶ。枠が埋まらなくても追加走査しない。

不一致枠の候補は両エンジンの推奨手。一致枠では共通推奨手と、異なる実戦手または既存完了反復に現れた別手を使う。二つ目がなければ1手のみ。合法手生成順の先頭を「第二候補」として補わない。完全に同一の10万節点の強制探索結果が保存済みなら再利用する。

候補の点数は、同じ親局面・同じ評価器による強制root探索で比較する。完了した手・得点・PVを一組として扱い、打切り後の返却手へ別の完了反復の得点を付けない。`lowerbound`、`upperbound`、詰み表示、未完了は通常の確定cpと混ぜない。選択的探索の`exact`も理論的な正解を意味しない。

符号は局面ごとに根の手番側へ統一し、尺度・手番補正をソースと設定から説明する。異なるエンジンのcp差をそのまま損失量にせず、まず各エンジン内の候補順位を見る。深さ差も記録する。二段階で順位が変わる例は未解決として残す。双方のPVを合法再生し、相手の応手で差がどう生まれるかを確認する。詰みや勝利を主張する場合は別途証明を要する。

## 観測から次の変更を決める

| 観測 | 次に調べる箇所 |
| --- | --- |
| 同じr6の静的評価が一致しない | 特徴量、駒打ち・成り・捕獲・玉移動の更新、符号、尺度、補正。再計算との一致を確認してから局所修正 |
| 静的評価は揃い、候補を強制するとSekireiも良いと評価する | 手の順序、枝刈り、減少探索、再探索、rootへの節点配分。強制探索で見つかったことだけでは原因を決めない |
| 計算量を増やすとSekireiの順位が変わる | 見逃した応手と探索量を確認。時間配分の仮説は後の同時間試験で調べる |
| 同じr6を使う両エンジンが同じ疑わしい判断をする | 別重みや証明可能な手順で反証し、r6の評価の弱点を調べる |
| やねうら王の候補が深い比較で悪化する | 参照側の誤り・不安定さとして残し、Sekireiへ模倣させない |

再現例が一つあれば原因診断や正しさの修正へ進める。NNUE学習候補へ進む場合は、既存D7計画に沿って元対局をまたぐ同種問題を確認し、訓練・開発・独立確認を対局単位で分ける。選んだ難局面だけに合わせて学習せず、一般局面での悪化も測る。

修正後は既知局面で機構が変わったかを確認し、未使用の別対局で改善・悪化・未解決を数える。探索定数調整と探索変更のscreenはAGENTS.mdの材料評価・自前序盤条件に従う。NNUE候補の初期screenは最大500色反転ペア以内で、進行・打切り規則を対局前に固定する。候補ごとの独立確認を通った場合に採用を判断する。既存の棄却結果を延長・合算しない。
