# F01：終端情報と確定境界の表参照をまとめる

2026-11-17。P01の1,527サンプル中475がlookup_with_dependencyの最上位フレームだった。
この関数は終端表を参照し、なければ確定境界表を参照する。両方のキーは同じ局面hash。
単独候補F01では両者をPositionFacts { terminal, bounds }という一つの値へまとめる。
残り深さ付き未完了表、ハッシュ関数、探索順、閾値、反復、着手処理は変えない。
終端を優先し、終端記録と境界記録は互いを消さず、現行と同じ結果を返す。

同じ固定9f3539fから基準とF01を隔離ビルド。両方の計数版を6問各1回、
計数なし版を各5回、候補の新証明を6回、別process再生を6回。
solver計78起動、checker6起動、全体20分以内。1T・重みなし・深さ25・
999,999訪問・内部8秒・外側12秒・RSS2GiB・ログ2MiB/起動。ビルド/テストは各5分・1ジョブ。
過去の結果を混ぜず、初手・標準nodes・完全着手数の全件一致を要求する。
表参照数はlookup_with_dependency内のmap.getの回数を数え、書込みや初期化を含めない。
計数版の時間を速度判定に使わない。

進行条件は内部時間中央値合計10%以上短縮、各問の悪化max(基準10%,0.1ms)以内、
RSS増max(基準10%,1MiB)以内、新しい全応手証明の別process再生成功。
5回の中央値・範囲、改善/悪化数、最大時間問除外も保存する。
不通過なら再試行せず停止。通過時は凍結して別入力の確認を別登録する。
既知6問だけで共有本体へ採用しない。K01の容量調整やC01/O01の再試行はしない。

検査：既存mateテストと明示ignore回帰、終端の優先、terminalとboundsの共存、
矛盾境界・反復依存・中断・深さ再利用の既存条件を確認する。
実行物・差分・入力・実行器・計画のhashを結果の観測前に登録する。
