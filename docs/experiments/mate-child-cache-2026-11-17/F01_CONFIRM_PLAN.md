## 観測と判断

全90起動について終了、初手、節点、内部時間、RSS、上限内完了、実行物 ID を記録する。各局面の5回の中央値と範囲、基準/候補の中央値合計、最大時間局面を除いた合計、改善/悪化局面数、問別時間差、最大 RSS 差を表示する。回答なしは両版で一致しても不詰の証明とは扱わない。

共有本体への統合レビューに進む条件を以下に固定する。これは実用上の選別規則であり、統計的有意差や棋力向上の証明ではない。

1. 全90起動が制限内に正常終了し、各対の初手と節点が一致する。候補が詰みを返した全局面で、新規の全応手証明が生成され、別プロセスで再生できる。詰み回答が2局面以上ある。
2. 候補の局面別中央値合計が基準より短く、最大時間の1局面を除いても短い。9局面のうち6局面以上で中央値が短い。改善率に一律10%の下限は置かない。
3. 各局面の時間悪化は `max(基準中央値の10%, 0.1ms)` 以下、最大 RSS 増は `max(基準最大 RSS の10%, 1MiB)` 以下とする。

どれか満たさなければ `NO_ADOPTION` とし、元の `NO_PASS` を保持して #293 に結果を報告する。満たした場合は `ADVANCE_TO_INTEGRATION_REVIEW` とし、F01 を現行 main へ適用した差分を再確認する。焦点 mate テスト、明示 ignore 回帰、fmt、workspace test、clippy、必要な文書検査、ホスト CI を通し、コードと結果を PR にまとめる。CI カバレッジはホスト結果を確認し、長いローカル全量計測は重複実行しない。採用と issue クローズは PR のマージ後に確認する。どちらの判定でも、通常探索の棋力、他エンジン比、最短詰みには結論を出さない。
