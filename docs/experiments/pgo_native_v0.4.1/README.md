# Native PGO build screen

This qualifies a compiler-profiled build of unchanged Sekirei source at
`7c739cb44510f189bc366ccb1a0418fefde42d3f`. It does not change Rust search
logic, NNUE weights, pruning, or the default Cargo profile. Ordinary release
builds do not automatically use this profile.

## Observations

The same Apple M4, Rust 1.97.0 / LLVM 22.1.6, native target, Thin LTO, one
codegen unit and workspace release settings were used in both arms.

| Own evaluation / lane | PGO over native | Bootstrap 95% interval |
| --- | ---: | ---: |
| Synthetic, 1T elapsed | 0.93342 | 0.92952–0.93766 |
| Material, 1T elapsed | 0.91742 | 0.90951–0.92537 |
| Synthetic, 4T NPS | 1.05121 | 1.02412–1.07473 |

All 384 one-worker depth-12 searches matched bestmove, score, PV, nodes, depth
and bound. The profile-use core unit tests passed (345 passed, 4 ignored).
The final executable has no `__llvm_profile` runtime hooks; the instrumented
training executable was never included in speed measurements.

## Compiler profiles and boundaries

[The 64 training positions](compiler-profile-training.sfen) are fresh seeded
legal random playouts, generated by the frozen safe Rust environment adapter.
The board/hand/turn keys do not overlap the 31-position quick timing corpus.
[Provenance](training-provenance.json) records seed 20261015, owner identity,
move histories and hashes. These are compiler-profile inputs; exclude them
from future independent strength gates. No NNUE training or external
evaluation data is involved.

The synthetic evaluator is `HalfKpNetwork::random(20261014).to_bytes()`, using
absolute output and FV_SCALE=16. Profiles collect 128 one-worker searches
bounded by 100,000 nodes and 32 four-worker searches bounded by 100ms, split
between material and synthetic evaluation. Collection timings are excluded.

The release profile remains opt-level=3, lto=thin, codegen-units=1,
strip=debuginfo, panic=abort. Build baseline, generate and use in the same
checkout and target directory with `--target aarch64-apple-darwin`. Explicitly
retain `-C target-cpu=native` when replacing Cargo rustflags. The measured
phases used these additional flags:

```text
baseline: none
generate: -C profile-generate=<absolute raw directory>
          -C llvm-args=-instrprof-atomic-counter-update-all=true
use:      -C profile-use=<absolute merged.profdata>
          -C llvm-args=-pgo-warn-missing-function
```

Use `LLVM_PROFILE_FILE=<absolute raw directory>/train-%m.profraw` only for
normal-exit collection, then merge with the matching rustup `llvm-profdata`.
The atomic-counter option is an LLVM internal option verified in 22.1.6;
do not silently fall back to non-atomic multi-thread collection on another
toolchain. Regenerate profiles when source, toolchain or build settings change.
See the [rustc PGO instructions](https://doc.rust-lang.org/rustc/profile-guided-optimization.html),
[Cargo rustflags precedence](https://doc.rust-lang.org/cargo/reference/config.html#buildrustflags),
and [pinned LLVM atomic lowering](https://github.com/llvm/llvm-project/blob/llvmorg-22.1.6/llvm/lib/Transforms/Instrumentation/InstrProfiling.cpp#L102).

## Measurement protocol

Each fixed-depth lane uses the first 16 quick positions, three per-position
ABBA repeats, fresh processes, Hash=64, depth 12, no cost counters, and exact
completed-result/PV replay checks. Four workers use one ABBA quartet per
position, movetime 1000ms, Hash=64, SearchMode=Auto, SpecTopN=0, no diagnostics
or book, MoveOverhead=0 and a position-readyok wall-timing barrier.

Continuous one-second PID/PPID/CPU/command-name samples and boundary checks
reject whole ABBA attempts for outside compiler load, high outside CPU or
low disk space. No process arguments are recorded. Only those host/disk
conditions permit up to three attempts; signature mismatches always fail the
candidate. Timing below20ms (1T) or700ms (4T) is retained but excluded without
retry. Require eight eligible positions per lane.

Ratios aggregate log paired means by position; intervals use 5,000 position
bootstrap samples, seed20261014. All numerical gates were fixed before
timing: 1T elapsed upper bound below1 for both evaluators, 4T NPS point at
least1 and lower bound at least0.98. [results.json](results.json) binds inputs,
binaries, profiles, the raw report and complete summaries. Frozen binaries,
raw stdout/JSONL, continuous host samples and the unchanged raw report are
retained locally under `results/yaneura-pgo-20261015/`.

These are shared-host development measurements, not playing-strength
evidence. Four-worker search trees can differ through TT scheduling. Any
pinned-opponent measurement is separate and cannot choose this build or
search defaults.
