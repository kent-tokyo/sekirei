# 公開上級詰将棋の有界診断 PT01

## 問い

原典へ遡れる13～25手詰の局面で、現行SekireiのDFPNは限られた時間・節点内に詰みを証明できるか。`disproven` が出た場合は、公開データの検証済み手順と独立に突き合わせて正しさを調べる。`unknown` は予算内で未解決と扱う。

## 入力と事前固定条件

- 入力: Open Tsume, `tokoroten/edo_era_tsume_shogi`, commit `6231b40e6630259d09034be9c28646b5069337fc` の将棋無双・将棋図巧の `problems/`。原典作品はpublic domain、データ記録はCC0。各 `solution_usi` は一本道の合法性・連続王手・最終詰みについて検証済み。全分岐の最短性・唯一性は保証されない。
- 選定: 両作品から番号順に、検証済みかつ記録手順13～25手の先頭6題ずつ。固定ID: `musou-004`, `musou-007`, `musou-010`, `musou-017`, `musou-021`, `musou-023`, `zukou-002`, `zukou-005`, `zukou-007`, `zukou-012`, `zukou-013`, `zukou-014`。結果を見て入れ替えない。
- 実行: `target/release/sekirei` のSHA-256を記録。冷起動1題1プロセス、`SearchMode=Dfpn`, `Threads=1`, `go depth <記録手数> nodes 50000 movetime 1000`。外側の壁時計上限4秒、出力は対象USI行のみ。最大12題、逐次実行。バイナリとソースの同一性は別途確認する。
- 判定: `proven` はその深さ内の詰み証明。`unknown` と壁時計停止は未解決。`disproven` はデータの一本道が少なくとも詰むことと食い違う可能性があり、手順の再検証と独立再現後にissue候補とする。返却手だけでは証明・不具合としない。
- 停止: 12題を終えたら次の問いと予算を記録して再順位付けする。異常なRSS、未終了プロセス、出力肥大化、他作業への圧迫を見たら即停止する。未解決例の上限を結果に合わせて延長しない。
