# 公開「次の一手」から実戦型の探索課題を探す（NM01）

目的は、非詰みの公開実戦問題からSekirei r6の改善可能な手選びを探すこと。掲載解答は参考手であり、最善手の証明とはしない。問題正答率、診断上の手の差、実戦棋力を別の量として扱う。元の公開詰将棋試行や既存の独立対局判定を変更しない。

## 取得・固定の契約（解析前）

- 入力源はLishogiの公開 `/training/{theme}` ページの埋込 `LishogiAnalyse['puzzle']`。カテゴリは `fork,pin,sacrifice,joiningPawn,edgeAttack,equality,advantage,opening,middlegame,endgame,crushing` の順に巡回する。最大60 HTTP GET、60秒。取得元URL、取得時刻、HTTP status、raw SHA-256、puzzle ID、game ID、元SFEN、開始手、解答列、themesを記録する。手順とラベルの生成元は別途確認し、未確認なら学習・候補選定の教師にはしない。
- まず出現順の一意IDから、`mate`/`tsume`系テーマを含まない非詰み問題を最大24件採る。元対局・盤面の重複は除外し、合法な開始手を適用して問題局面を作る。技術的に24件に届かなければ取得数と理由を記録し、同じ上限の順送りはしない。
- 取得・合法再生後、game ID単位で先に集合を分離する。独立の元対局を持つ先着半数を開発用、残りを未使用確認用とし、確認用の探索結果は修正候補を固定するまで見ない。カテゴリと出典を両集合に残す努力はするが、結果を見て配分を変えない。
- SFEN、手番、指し手、双方の玉、局面の重複を検証する。出典に不一致があれば当該件は保留し補正しない。問題原文・図の複製は保管しない。出典ID・局面・必要最小限の指し手を私有の診断資料とする。

## NM01の最小診断と停止規則（結果を観測する前に固定）

- 現行ソース・実行ファイル・公開r6重みのSHA-256を記録。r6は `FV_SCALE=24`、absolute、1T、`SpecTopN=0`。既存 `search_diagnostic` を使い各位置を冷プロセスで100msと1000ms、各最大100,000/1,000,000節点で通常探索する。時計が厳密に揃わなければ固定節点の探索診断に限定する。候補強制探索は通常手と参考手に限り、開発用の不一致最大4件、各最大1,000,000節点。全体探索の外側上限60秒、追加RSS目安512MiB、出力8MiB。予算に達したら既処理件数で停止し、延長しない。
- `bestmove`とPVの合法性、完了深さ、経過時間、score種別、100ms→1000msの変化、強制候補の相手最善応手を記録。参考手と不一致でも、別の同等手・評価不明・探索不足を区別する。強制候補のスコアがexactで完了しないときは優劣未判定。単一局面の差から探索原因を断定しない。
- 開発用で「通常探索は見落とし、強制候補なら一貫した良い応手列を得る」同種例が複数あれば、該当する探索機構の一候補を隔離して作る。複数なくても明確な失着が1件なら再現と救済手を確認し、候補を作るか費用対効果で判断する。候補ができたら未使用確認用を同一条件で一度だけ測り、改善/悪化と同時間コストを併記する。既知問題の正解率のみで既定採用しない。採用には別の独立対局資格が必要。

## 実行記録

[NM01結果](RESULTS.md)を確認。24題を合法復元して開発12/未使用確認12へ分け、開発12題の固定節点診断と不一致2題の強制root比較を完了した。既定変更・棋力向上の証拠はまだない。現在の共有worktreeにあった他作業の差分は保持した。

### NM01a: 10万節点で回復が遅れた1例の機構診断（実行前登録）

開発用 `suLWr` は10万節点の通常探索では参考手と異なり、100万節点では一致した。候補固定では参考手からmate scoreを返した。これは採用候補の成績ではない。次に同一binary/r6/局面・10万節点・1Tで `--iteration-trace` を一度だけ記録し、最初のroot順序と完了深さごとの先頭手を確認する。外側4秒、出力1MiB。もし参考手が生成されていないなら手生成の問題、後方にいて探索不足なら順序の仮説、上位で探索済みなら別機構を検討する。原因を断定せず、結果に合わせて同じ例の試行上限を延長しない。
